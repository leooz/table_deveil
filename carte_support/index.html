Table d'éveil · circuit imprimé v1

La carte support de l'ESP32

Une carte de 70 × 70 mm qui remplace la plaque à trous. Le DevKit s'enfiche dessus, chaque zone de la table a son connecteur avec sa masse, et les LED, le haut-parleur, un bouton libre, un bouton reset et une LED d'état sont intégrés. Plus aucun fil à souder sur l'ESP32.

Pourquoi garder le DevKit

Une carte avec la puce ESP32 nue demanderait d'ajouter le port USB, la puce de programmation, le régulateur 3,3 V et le circuit de démarrage, de souder des composants de 1 mm, et de respecter les règles de l'antenne. C'est un projet à part entière. Ici le DevKit reste enfiché sur deux barrettes femelles : il se programme comme avant, et s'il grille, il se remplace en dix secondes.

Même chose pour les connecteurs : les embouts de tes fils sont des pins mâles de breadboard, donc la carte reçoit des barrettes femelles au pas de 2,54 mm. Tu branches tes fils tels quels.

Les connecteurs

Chaque signal a sa broche de masse juste à côté, sur la rangée marquée GND. Un bouton se branche donc toujours sur deux broches voisines, sans se demander où trouver la masse.

Comment on a trouvé deux broches de plus

Les 23 broches utilisables étaient prises. Le switch 3 positions occupait deux broches ; il n'en prend plus qu'une, lue en analogique. Avec le levier sur A la broche lit 0 V, sur C une résistance donne 1,65 V, au centre elle reste à 3,3 V. Cette broche libérée accueille SW1, qui libère à son tour D22 pour la LED 1, ce qui laisse D2 à la LED d'état. Le bouton libre prend D5, la dernière broche disponible. Le budget est maintenant de 23 sur 23.

Le commander

  1. Récupère le fichier table_eveil_gerbers.zip que je t'ai envoyé. Il est aussi dans le dépôt, dossier pcb/fab/.
  2. Va sur jlcpcb.com (ou pcbway.com) et clique sur « Order now ». Dépose le zip : le site détecte 2 couches et 70 × 70 mm, et affiche un aperçu des deux faces.
  3. Garde les réglages par défaut : épaisseur 1,6 mm, finition HASL, 5 exemplaires. Seule la couleur est à ton goût. Compte 2 à 5 € la carte plus 10 à 20 € de port, livrée en une à deux semaines.
  4. Ne prends pas l'assemblage : tous les composants sont traversants, tu les soudes toi-même en une demi-heure.

Si tu préfères un fabricant européen, Aisler (Allemagne) accepte le même zip. C'est plus cher, mais plus rapide et sans frais de douane.

À vérifier avant de payer

Trois mesures, sinon la carte ne servira à rien

  • L'écart entre les deux rangées de broches du DevKit, d'axe à axe : 25,4 mm. Certains DevKit sont à 22,86 mm.
  • L'ordre des broches, vu de dessus avec l'USB en bas : la rangée de gauche commence par EN, VP, VN, D34 ; celle de droite par D23, D22, TX0, RX0. Les marquages EN et D23 sont imprimés sur la carte pour ce contrôle.
  • L'entraxe des trous de fixation : 49 mm, en carré, prévus pour des vis M3. Mesure au pied à coulisse si tu peux.

Si une mesure diffère, dis-le-moi : chaque valeur est un seul paramètre dans le script, la carte se régénère en une minute.

Ordre de soudure

Du plus bas au plus haut, pour que la carte tienne à plat pendant que tu soudes.

  1. Les résistances et la diode. Elles sont sous le DevKit, donc à souder en premier. Les valeurs sont listées ci-dessus ; la bague de la diode va du côté marqué K.
  2. Le transistor Q1, face plate du côté du dessin plat sur la carte.
  3. La LED d'état, patte courte (cathode) dans le trou carré.
  4. Les deux boutons. Ils ne rentrent que dans un sens.
  5. Toutes les barrettes femelles, en commençant par les deux 1 × 15 du DevKit. Enfiche le DevKit dedans pendant la soudure : les barrettes resteront parfaitement alignées.
  6. Premier test sans rien brancher : branche l'USB, la LED rouge du DevKit s'allume ; appuie sur RESET, le moniteur série doit afficher le redémarrage. Puis branche les zones une par une et vérifie chacune au moniteur série.

À reporter dans le firmware

// ---- brochage carte support v1 ----
const uint8_t NB_BOUTONS = 13;
const uint8_t PIN_BOUTON[NB_BOUTONS] = {
  13, 14, 27, 32,   // 0-3   piano
  18, 19, 21,       // 4-6   formes
  26, 25, 23,       // 7-9   maracas, trappe, bongo
  33, 39,           // 10-11 guitare (39 : pull-up sur la carte)
  15                // 12    livre
};

const uint8_t PIN_SW1      = 36;  // VP, pull-up sur la carte, INPUT
const uint8_t PIN_SW2      = 35;  // lecture analogique, voir lireLayer()
const uint8_t PIN_SLIDER   = 34;
const uint8_t PIN_BTN      = 5;   // bouton libre, INPUT_PULLUP
const uint8_t PIN_LED_ETAT = 2;
const uint8_t PIN_LED[4]   = {22, 4, 16, 17};
const uint8_t PIN_HP       = 12;  // PWM : tone() ou ledcWriteTone()

// A = 0 V, C = 1,65 V, centre = 3,3 V
uint8_t lireLayer() {
  int v = analogRead(PIN_SW2);       // 0..4095
  if (v < 1000) return 0;           // A
  if (v < 3000) return 2;           // C
  return 1;                          // centre
}

void initBroches() {
  for (uint8_t i = 0; i < NB_BOUTONS; i++)
    pinMode(PIN_BOUTON[i], PIN_BOUTON[i] >= 34 ? INPUT : INPUT_PULLUP);
  pinMode(PIN_SW1, INPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  pinMode(PIN_LED_ETAT, OUTPUT);
  for (uint8_t i = 0; i < 4; i++) pinMode(PIN_LED[i], OUTPUT);
}

Le haut-parleur ne fait plus de mal à l'ESP32

Une broche de l'ESP32 ne fournit que quelques dizaines de milliampères. Le transistor Q1 prend le courant directement sur le 5 V de l'USB, la résistance de 47 Ω le limite à une centaine de milliampères, et la diode absorbe le retour de la bobine. Le firmware envoie simplement une note en PWM sur la broche 12. Une résistance de 10 kΩ garde cette broche à l'état bas au démarrage, comme l'exige l'ESP32.
